# Security

Denies by default; fails closed (an activity event that cannot be written stops the read); no SQL write on the app's tables from any GET; table and column names come only from the catalog; no column value in logs, errors, URLs or payloads; secret columns never shown; CSRF on every non-GET route. Criteria on masked columns never travel in the URL: `POST /data/:table/query` keeps them in the session (at most 20, each truncated, and the oldest dropped when the session grows past 1.5 KB; with a server-side session store they live in that store, so mind its protection) and redirects with an opaque token; the activity records column names only. A column is usable to filter, search or sort only if it is not hidden and is public or revealed; a hidden column or a masked one without a reveal never reaches a `WHERE` or `ORDER BY`. A field over a column that is not public is locked in Action forms, whatever the reveal: its submitted value is used only when the field is listed in `unlocked[]` and the operator may reveal its category (a hidden column is write-only and never read), else it is discarded; unlocking for reading records a value-free `backoffice.field.unlock` event and answers `no-store` (ADR 0002). A one-time secret is rendered once with `no-store` and never stored. Writes happen only through declared Actions (`creatable`, `editable`, `destroyable` or hand-written), each with a reason, a permission and an event. The non-GET routes are `POST /reveals`, `DELETE /reveals`, `POST /actions/:action_key`, `POST /actions/:action_key/preview`, `POST /actions/:action_key/fields/:field/unlock` and `POST /data/:table/query`.
