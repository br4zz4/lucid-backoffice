# Security

Denies by default; fails closed (an activity event that cannot be written stops the read); no SQL write on the app's tables from any GET; table and column names come only from the catalog; no column value in logs, errors, URLs or payloads; secret columns never shown; CSRF on every non-GET route. Criteria on masked columns never travel in the URL: `POST /data/:table/query` keeps them in the session (at most 20, per table and context) and redirects with an opaque token; the activity records column names only. A column is usable to filter, search or sort only if it is not hidden and is public or revealed; a hidden column or a masked one without a reveal never reaches a `WHERE` or `ORDER BY`. A field over a masked column is locked in Action forms and its submitted value is discarded. A one-time secret is rendered once with `no-store` and never stored. Writes happen only through declared Actions (`creatable`, `editable`, `destroyable` or hand-written), each with a reason, a permission and an event. The non-GET routes are `POST /reveals`, `DELETE /reveals`, `POST /actions/:action_key` and `POST /data/:table/query`.
